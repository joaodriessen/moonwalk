# Starlight fork — phase 1 design

Starlight becomes a sovereign fork of moonlight-qt: the engine that already proved itself (decode 0.6 ms,
queue 0.9 ms — measured at its floors in the 2026-07-13 latency program) under a UI worth using.

## Doctrine

- **Pristine engine.** `app/streaming/` and `app/backend/` stay as close to upstream as possible; our changes
  there are small, commit-isolated, and upstream-shaped. Upstream tracking = `upstream` remote + cherry-picks,
  the same intake discipline as the Skylight host fork.
- **The UI is the fork.** `app/gui/` is replaced by a HIG-designed QtQuick Controls 2 interface — design
  contract: `2026-07-13-hig-mockup.html` (owner-approved). Sidebar lists hosts only; every host owns its page:
  connect hero, quality presets, inline grouped settings. No app-level Settings tab. System typography
  (Inter on Linux — SF Pro and SF Symbols are Apple-platform-licensed and never shipped here), macOS control
  grammar, dark and light both first-class.
- **No invented settings.** Every control binds to a StreamingPreferences property that already exists (or the
  wrapper-era `local_cursor`, promoted from env-gate to preference). Telemetry shows only real data.
- **Phase fences.** Phase 1: UI + native fastest-path + cursor pref. Phase 2: cursor-shape channel (with the
  Skylight host). Phase 3 (only on measured need, possibly never): stream presentation inside the app window —
  the render path is not touched before then.

## Phase-1 scope (this repo state)

1. Base: moonlight-qt master (c0c4d605) + the two wrapper-era patches landed as code (929c4f59):
   local-cursor-in-absolute-mode and the addressOverride guard.
2. HIG UI per the mockup, bound to existing preferences only; pairing/connect/quit flows preserved; CLI entry
   points kept working; old QML left in-tree unreferenced this phase.
3. Native prefer-fastest address selection at session start (TCP-probe all candidate addresses, median of 3,
   pick fastest live; precedence: `MOONLIGHT_HOST_OVERRIDE` env > probe > stored record) — retires the
   wrapper's Moonlight.conf pinning and, eventually, the wrapper itself.
4. `localCursor` as a persisted preference (effective = pref OR env).

## Relationship to the wrapper (github.com/joaodriessen/moonwalk)

The wrapper (Rust core + Kirigami launcher) stays installed and untouched until this fork earns its place via
owner sign-off. Its good ideas live on here natively; its patches directory is this repo's ancestor record.
